# ShopPilot 阶段六设计：向量检索与 RAG

日期：2026-10-28
状态：已确认

## 意图

顾客的问题常常用词模糊——问「杯子」而库里叫「马克杯」，问「裂了」而工单写
「运输破损」。纯字面匹配召回不足，客服只能回答「没查到」。

这一轮引入向量检索：把商品与工单嵌入成语义向量，按意思而非字面找资料，
并让 AI 基于检索到的真实记录回答。

## 目标

1. 商品与工单写入时同步生成向量（双写）
2. AI 可通过 `search_knowledge` 按语义检索
3. `lookup_product` 字面查不到时自动退到语义检索
4. 顾客只能检索到公开商品与自己名下的工单
5. 索引可全量重建
6. 向量服务故障不影响业务写入

## 非目标

- 政策/FAQ 知识库（暂无数据源）
- 文档切分（chunking）与混合检索
- 重排序模型
- 多向量/多字段检索
- 索引增量同步（CDC）

## 反目标

- 不允许向量库成为事实来源——MySQL 始终是唯一真相
- 不允许向量写入失败导致主业务流程失败
- 不允许跨顾客检索到他人私有数据

## 技术选型与理由

| 组件 | 选择 | 原因 |
|---|---|---|
| 向量库 | **Milvus Lite** | Docker Hub 不可达，无法拉取 Milvus 镜像；Lite 是 pip 包，接口与服务端一致，后续可平滑切换 |
| 嵌入模型 | **BGE-M3**，经硅基流动 API | HuggingFace 不可达；本机无 GPU（AMD 集显），本地跑 BGE-M3 需 2.3GB 权重且 CPU 推理慢；API 调用省去下载与 2.2GB 内存 |
| 嵌入维度 | 1024 | BGE-M3 输出维度 |
| 相似度 | 内积（IP） | 向量已归一化，等价余弦 |

## 架构

```
写入路径：
  业务写 MySQL ──→ 成功 ──→ 嵌入 ──→ 写 Milvus
                     │                  └─ 失败只记日志，不回滚 MySQL
                     └─ 失败则整体失败

检索路径：
  AI 调 search_knowledge ──→ 嵌入查询 ──→ Milvus 检索 ──→ 阈值过滤 ──→ 返回
```

## 集合设计

```
collection: shoppilot_knowledge
  id          VARCHAR(64)   主键，"product:{id}" / "work_order:{no}"
  source      VARCHAR(16)   product | work_order
  source_id   VARCHAR(64)   原表主键
  visitor_id  VARCHAR(64)   空串 = 公开数据
  text        VARCHAR(2048) 原文，便于调试与回溯
  vector      FLOAT_VECTOR(1024)

索引：FLAT，metric = IP
```

`FLAT` 而非 `IVF_FLAT`：当前数据量（百余条）下 FLAT 精度最高且无训练开销，
数据量上万后再换。

## 访问隔离

检索过滤条件固定为：

```sql
visitor_id == "" or visitor_id == "<当前顾客>"
```

商品是公开数据（`visitor_id=''`），工单是私有数据。这条过滤在向量库层
执行，不依赖应用层事后过滤——后者容易在改动中遗漏。

## 双写策略

| 场景 | 行为 |
|---|---|
| MySQL 写入成功、向量写入失败 | 记录 warning，接口照常返回成功。索引可重建 |
| MySQL 写入失败 | 整体失败，不产生孤儿向量 |
| 嵌入服务不可用 | 同上，降级为纯关键词检索 |

`upsert_documents()` 内部捕获所有异常并返回写入条数，从不向调用方抛出。

## 相似度阈值

`RELEVANCE_THRESHOLD = 0.5`。低于阈值的命中不返回给模型——宁可不给资料，
也不要把不相关内容塞进上下文让模型硬套。

实测参考值（BGE-M3 + 内积）：

| 查询 | 命中 | 分数 |
|---|---|---|
| 杯子裂了怎么办 | 运输破损工单 | 0.767 |
| 有没有蓝色的保温杯 | 蓝色保温杯商品 | 0.677 |
| 退货流程 | 发货延迟工单（不相关） | 0.636 |

第三例说明阈值不能定太高，但「不相关」的 0.636 仍会被放行——阈值是
粗筛，语义质量由模型判断。

## 商品检索的语义回退

`lookup_product` 先做字面匹配。查不到时调 `search_knowledge` 取商品类
结果，再用 `source_id` 回表取完整信息。返回值标记 `match: exact|semantic`，
便于排查。

这样「杯子」能命中「马克杯」，而「手机」不会因单字「手」误命中「手工青花」。

## Milvus Lite 的文件锁限制

Lite 对数据文件加独占锁，**同一时刻只能有一个进程打开**。由此产生：

- 服务运行时，`scripts/reindex.py` 会失败（`DataDirLockedError`）
- 因此提供 `POST /api/admin/reindex`，在服务进程内执行重建

这是 Lite 模式的固有限制。切换到 Milvus Standalone（Docker）后消失，
届时本接口可保留作为运维入口。**生产环境该接口必须加鉴权**，当前未加。

## 环境变量

| 变量 | 说明 |
|---|---|
| `SILICONFLOW_API_KEY` | 嵌入服务密钥 |
| `EMBED_MODEL` | `BAAI/bge-m3` |
| `EMBED_BASE_URL` | `https://api.siliconflow.cn/v1` |
| `VECTOR_DB_PATH` | Milvus Lite 文件路径 |

注意变量名不能用 `MILVUS_URI`——pymilvus 会把它当作服务端地址解析，
相对文件路径会被判为非法 URI。

## 验收标准

1. 商品与工单写入后，向量在数秒内可检索
2. 「杯子裂了」能召回运输破损工单
3. 「杯子」能通过语义回退找到马克杯
4. 「手机」不会误命中任何商品
5. 顾客 A 检索不到顾客 B 的工单
6. 嵌入服务不可用时，MySQL 写入仍成功，检索降级为空
7. `POST /api/admin/reindex` 可全量重建
8. `uv run pytest` 全绿

## 留给构建者的决定

- 批量嵌入的分批大小（当前 32）
- `text` 字段是否要存原文（当前存，占空间但便于排查）

# ShopPilot 阶段九设计：知识库录入界面

日期：2026-10-28
状态：已确认

## 意图

此前录入知识只有一条路：写 Markdown 放进 `data/faq/`，敲命令导入，再敲命令
重建索引。对非开发者完全不可用——要会写 Markdown、会用命令行，还得知道
重建索引要先停服务（Milvus Lite 独占文件）。

这一轮把录入搬到 Web 界面，让知识维护不依赖开发者。

## 目标

1. 可视化管理知识：列表、分类筛选、新建、编辑、删除
2. **保存即生效**：写完立刻能在顾客对话中检索到，不用手动重建
3. 停用而非删除：暂时下架可随时恢复
4. 录入时校验，避免垃圾进库

## 非目标

- 富文本编辑（纯文本 + 简单 Markdown）
- 版本历史与回滚
- 多人协作与权限分级
- 附件上传
- 批量导入界面（继续用脚本）

## 存储形态的转变

**Markdown 文件从「事实来源」降级为「初始种子数据」。**
之后所有增删改都写 MySQL，`data/faq/*.md` 与数据库会不一致，这是接受的取舍：

- 保留 md 作为项目初始化素材，新环境一条命令灌入基础政策
- Web 界面是唯一的事实来源
- 想改种子数据才动 md，改完重跑 `import_faq` 会覆盖同名条目

## 数据模型变更

`faq_documents` 增加一列：

```sql
enabled TINYINT(1) NOT NULL DEFAULT 1
```

`enabled=0` 的条目保留在库里但不进索引。相比直接删除，停用的好处是
误操作可恢复，且保留了历史内容的审计线索。

`init_db()` 通过 `information_schema` 检测并补列，对已有库幂等生效。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/faq` | 列表，含停用项与 `enabled` 标记 |
| GET | `/api/admin/faq/categories` | 已有分类与条目数 |
| POST | `/api/admin/faq` | 新建 |
| PUT | `/api/admin/faq/{id}` | 编辑 |
| DELETE | `/api/admin/faq/{id}` | 删除，同步删向量 |
| POST | `/api/admin/faq/{id}/toggle?enabled=` | 启用/停用，同步索引 |
| GET | `/api/admin/faq/search?q=` | 调试用：看原始分数，绕过阈值 |
| POST | `/api/admin/reindex?drop=` | 全量重建索引 |

**暂不鉴权**，与既有 `/api/admin/reindex` 一致。这是本地开发的临时状态，
上线前必须加保护——已在 README 与本文档标注。

### 写入即同步

保存后立刻嵌入并 upsert 到 Milvus，不等批量重建。删除时同步删向量。
这是硬要求：否则改完政策，顾客还能搜到旧内容。

失败不阻断：MySQL 已写入，只记日志，可通过重建索引补回。

## 录入校验

| 字段 | 规则 | 理由 |
|---|---|---|
| 标题 | 2–64 字 | 太短无意义 |
| 小节名 | 2–64 字 | **参与嵌入**，是检索信号，必须写具体 |
| 分类 | 非空，可自由输入 | 保持分类整洁 |
| 正文 | 20–2000 字 | 太短没信息量，太长检索会被稀释 |

前端与后端双重校验（前端即时提示，后端 `Pydantic` 兜底）。

## 界面

`/admin`，独立页面，原生 JS + ES module，不引框架。

```
┌──────────────┬────────────────────────────────┐
│ 分类 chips    │ 标题 [____________________]    │
│ 全部 47 …     │ 小节 [____________________]    │
├──────────────┤ 分类 [____________________]    │
│ 价格保护规则  │ 正文 ┌──────────────────┐      │
│ 七天无理由…   │      │                  │      │
│ 物流延迟…     │      └──────────────────┘      │
│              │ 0/2000 字                      │
│              │ [保存] [停用] [删除]           │
└──────────────┴────────────────────────────────┘
```

停用项在列表中显示删除线与「已停用」标记，不隐藏——需要能被找回来。

## 发现并修复的两个问题

### 1. Prompt 路由缺口

实测发现：录入新知识后，顾客问「XX 商品怎么保存」，模型走了 `lookup_product`
而不是 `search_knowledge`——因为它看到商品名就判定是商品问题。

修法：prompt 明确「判断依据是问题在问什么，不是句子里有没有出现商品名」，
并在 `lookup_product` 查不到时返回提示「若问的是使用规范、保养、存放等
政策问题，改用 search_knowledge」。

### 2. 测试被静默跳过

`tests/test_retrieval.py` 与 `tests/test_admin_faq.py` 都用
`skipif(not os.getenv("SILICONFLOW_API_KEY"))` 做前置条件。但 pytest 收集
阶段没加载 `.env`，环境变量为空，**18 项测试全部静默跳过**，报告仍显示绿。

加了 `tests/conftest.py` 统一 `load_dotenv()`。这是一个危险的失败模式：
跳过与通过都是绿色，看不出区别。

## 验收

1. 新建知识后立即能被检索（实测 0.797 分排第一）
2. 编辑后新内容生效
3. 停用后检索不到，列表仍可见
4. 删除后彻底消失
5. 分类下拉来自已有分类
6. 前后端校验均拦截非法输入
7. 全量测试 123 项通过（此前 109 项里有 14 项被跳过）

## 已知限制

- **无鉴权**：任何能访问服务的人都能改知识库
- **无版本历史**：改错了无法回滚，只能靠停用降低影响
- **并发编辑会互相覆盖**：没有乐观锁
- **md 与数据库会漂移**：两边都可改，以后者为准
- Milvus Lite 单进程独占，`scripts/reindex.py` 在服务运行时必然失败，
  必须走 `/api/admin/reindex`

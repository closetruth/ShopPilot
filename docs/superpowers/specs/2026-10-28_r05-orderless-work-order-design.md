# ShopPilot 阶段五设计：无订单工单

日期：2026-10-28
状态：已确认

## 意图

此前工单强制关联订单。但投诉服务态度、咨询退换货政策、反馈页面问题这类
诉求本来就不对应某一笔订单，顾客在系统里根本找不到「该选哪一单」，
只能被客服要求「提供订单号」，体验是断的。

这一轮让工单可以不挂订单，同时不放松售后类工单的订单要求。

## 目标

1. 咨询、投诉建议、其他三类工单无需订单号即可提交
2. 运输破损、发货延迟、质量问题、退换货四类仍强制订单
3. 面板提供独立提单入口，不依赖订单列表
4. 无订单工单的去重按「顾客 + 类型」判定

## 非目标

- 工单与订单的多对多关联
- 顾客自行把无订单工单补挂到某笔订单
- 客服侧工单处理

## 反目标

- 不允许售后类工单脱离订单存在（无法核实到底是哪笔货）
- 不允许无订单工单因 NULL 比较失效而无限重复创建

## 规则划分

| 问题类型 | 订单号 |
|---|---|
| 运输破损 | 必填 |
| 发货延迟 | 必填 |
| 质量问题 | 必填 |
| 退换货 | 必填 |
| 咨询 | 可选 |
| 投诉建议 | 可选 |
| 其他 | 可选 |

校验在 `WorkOrderCreate` 的 `model_validator` 里，而非 prompt——模型无法绕过。

## 数据模型变更

`work_orders.order_no` 与 `work_order_drafts.order_no` 改为 `NULL`。
`orders.order_no` 保持 `NOT NULL`（订单号本身就是订单的主键）。

`init_db()` 通过 `information_schema` 检测并执行 `MODIFY COLUMN`，
幂等且对已有库生效。

## 去重逻辑

```python
if order_no is None:
    WHERE visitor_id = ? AND order_no IS NULL AND issue_type = ? AND status IN (...)
else:
    WHERE visitor_id = ? AND order_no = ? AND issue_type = ? AND status IN (...)
```

必须显式分支：SQL 里 `NULL = NULL` 为 false，若不处理会导致
无订单工单永远查不到重复，无限创建。

## 接口变更

`POST /api/work-orders/drafts` 的 `order_no` 改为可选。
归属校验仅在 `order_no` 非空时执行。

## 前端

- 面板「我的订单」页签顶部新增「提交无订单工单（咨询 / 投诉建议）」按钮
- 表单类型下拉对无需订单的三类标注「（无需订单）」
- 用户选售后类但没订单时，前端拦住并提示从订单列表选择
- 卡片与列表把无订单显示为「未关联订单」，不显示 `null`

## AI 行为

prompt 增补：

- 四类售后必须订单号，可先 `list_my_orders` 找
- 咨询 / 投诉建议 / 其他 无需订单号，问题本身与订单无关时直接起草，
  不要把「请提供订单号」当必经步骤

## 验收标准

1. 面板点「提交无订单工单」，选「投诉建议」并填写描述，提交成功
2. 同类无订单工单重复提交被拒，返回既有工单号
3. 选「运输破损」但不带订单号时被拒，提示需要订单
4. AI 在顾客投诉客服时能直接起草无订单工单
5. 工单列表与卡片把无订单显示为「未关联订单」
6. 售后类工单仍强制订单，跨顾客订单仍被拒
7. `uv run pytest` 全绿

## 留给构建者的决定

- 「其他」归入无需订单类是否合适（当前归入，因为可能是纯反馈）
- 无订单工单在列表中的排序策略（当前按更新时间，与其他一致）

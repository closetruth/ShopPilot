# ShopPilot 阶段七设计：政策知识库

日期：2026-10-28
状态：已确认

## 意图

上一轮接入向量检索后，「退货流程」查出来的是发货延迟工单——不是检索算法
的问题，是**库里根本没有政策文档**。商品和工单两类数据答不了政策类问题。

这一轮补上知识源：导入真实的中文电商售后政策，按小节切分后入库并建索引，
让客服能引用具体条款回答，而不是说「以商品详情页为准」。

## 目标

1. 政策文档入库，按小节切分为独立知识条目
2. 政策条目写入向量索引，可语义检索
3. 回答政策问题时引用具体规则编号
4. 导入可重复执行，支持政策更新

## 非目标

- 政策管理后台
- 政策的多语言版本
- 政策与订单/工单的自动关联
- 政策变更的通知与版本对比

## 反目标

- 不允许模型编造政策条款——知识库没有就明说查不到
- 不允许把整篇长文档塞进上下文（按小节切分，只给相关段落）

## 数据来源

`hong356/carepilot` 的 `data/policies/`，11 篇中文电商售后政策，MIT 类开源。

## 切分策略

按 `## ` 二级标题切分，一个小节一条记录：

```
P-RET-001 / 运费承担 →
  七天无理由退货的退回运费由消费者承担。订单含运费险的，按 P-LOG-002…
```

理由：
- 单条内容聚焦，检索出来不带无关段落
- 政策文档常有 4–5 个主题，整篇嵌入会让向量被稀释
- 小节名本身是强信号（「运费承担」比正文更能表达主题）

11 篇文档切出 47 条知识。

## 数据模型

```sql
faq_documents(
  id          VARCHAR(64)  PK    -- "P-RET-001-3"
  doc_id      VARCHAR(32)        -- "P-RET-001"
  title       VARCHAR(128)       -- "七天无理由退货规则"
  category    VARCHAR(32)        -- "退货"
  version     VARCHAR(32)        -- 政策版本
  section     VARCHAR(128)       -- "运费承担"
  content     TEXT               -- 小节正文
  source      VARCHAR(256)       -- 源文件名
  updated_at  DATETIME(6)
)
```

`id` 由 `doc_id` + 小节序号构成，保证重复导入是幂等的 upsert。

## 向量化

FAQ 是公开数据，`visitor_id = ''`，所有顾客可见。

嵌入文本：`标题 小节名 正文`。三者拼接而非只嵌正文——「运费承担」单看
正文不易判断属于退货还是换货，标题提供上下文。

## 检索增强

`search_knowledge` 命中 FAQ 时**回表取完整字段**，而非直接用向量里存的
拼接文本。返回结构：

```json
{
  "source": "faq",
  "doc_id": "P-RET-001",
  "title": "七天无理由退货规则",
  "category": "退货",
  "section": "运费承担",
  "content": "七天无理由退货的退回运费由消费者承担…",
  "score": 0.730
}
```

带 `doc_id` 与 `title` 是为了让模型能说「根据七天无理由退货规则（P-RET-001）」，
也让排查时能定位到源文档。

## Prompt 约束

政策类问题（退货、退款、运费、发票、物流时效、价保、会员、投诉）**必须先查
知识库**，不得凭印象回答。同时要查订单时，两者并行而非二选一——顾客问
「快递没动」，既要定位是哪一单，也要说明平台对延迟的处理规则。

## 导入脚本

`uv run python -m scripts.import_faq`

- 解析 YAML frontmatter（id/title/category/version）
- 按 `## ` 切分小节
- upsert 到 MySQL，重复执行结果一致
- 索引重建另行触发（`scripts/reindex.py` 或 `POST /api/admin/reindex`）

## 实测检索质量

| 查询 | 首条命中 | 分数 |
|---|---|---|
| 退货流程是怎样的 | P-RET-001 / 退款金额与时效 | 0.703 |
| 退货运费谁出 | P-RET-001 / 运费承担 | 0.730 |
| 快递丢件了怎么办 | P-LOG-001 / 丢件处理 | 0.697 |
| 发票能开吗 | P-INV-001 / 开具条件 | 0.715 |
| 可以便宜点吗 价格保护 | P-PRI-001 / 适用范围 | 0.692 |

五问全部命中正确文档，且多数命中正确小节。

对话实测：

> 顾客：我想退一个杯子，运费谁出啊
> 客服：根据七天无理由退货规则（P-RET-001），无理由退货的退回运费由您承担；
> 如果订单有运费险，由保险公司赔付，单笔最高12元。若是质量问题、错发漏发等
> 商家原因，往返运费由商家承担（P-REF-002）。

「12 元」这个上限来自 P-LOG-002 的正文，不是模型编的。

## 验收标准

1. 11 篇政策导入为 47 条知识小节
2. 重复导入不产生重复记录
3. 五类政策问题均能命中正确文档
4. 客服回答引用政策编号
5. 索引重建后 FAQ 条目可检索
6. `uv run pytest` 全绿

## 已知限制

- 政策文档来自第三方开源仓库，条款内容是虚构的演示规则，**上线前必须替换为
  本店真实政策**
- 文档间交叉引用（如「见 P-LOG-002」）在切分后失去上下文，模型可能只答一半
- 政策更新需要重新导入 + 重建索引，没有增量同步

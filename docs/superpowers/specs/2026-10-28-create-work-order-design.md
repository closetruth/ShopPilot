# ShopPilot 阶段三设计：创建工单

日期：2026-10-28
状态：已确认

## 意图

顾客描述问题时，客服目前只能查已有工单，不能新建。顾客说「杯子收到就裂了」，
客服只能让他「联系人工」。这一轮让客服能**当场提工单**，顾客不必离开对话。

这是第一个**写操作**工具，风险高于查询：记录会真实落库、无法通过对话撤销。
因此设计重点不是"能不能建"，而是"如何不误建"。

## 目标

1. AI 能创建工单，收集订单号、问题类型、问题描述三项必填信息
2. **创建前必须获得顾客明确确认**，不允许 AI 单方面建单
3. 同一顾客、同一订单号、同一问题类型的未完结工单不重复创建
4. 工单强制归属当前顾客，无法为他人建单

## 非目标

- 修改或撤销已建工单
- 工单流转、指派、结案
- 图片/附件上传
- 通知顾客（短信/邮件）

## 反目标

- 不允许模型在顾客未确认时调用创建工具
- 不允许同一订单同类型堆积重复工单
- 不允许把顾客描述原样当工单标题——需归类到固定枚举

## 交互流程

```
顾客：杯子收到的时候裂了
   ↓
AI：调用 lookup_product / lookup_work_order 确认商品与订单
   ↓
AI：复述待建工单（订单号 + 类型 + 描述），请顾客确认
   ↓
顾客：确认 / 好 / 可以
   ↓
AI：调用 create_work_order → 返回工单号
   ↓
AI：告知已提交，工单号 XXX
```

确认环节不做机械的状态机，由 prompt 约束：创建工具的描述里写明
「仅在顾客明确同意后调用」，并把未确认就调用视为错误。

## 数据模型变更

`work_orders` 增加两列：

```sql
priority    VARCHAR(16) NOT NULL DEFAULT '普通'
source      VARCHAR(16) NOT NULL DEFAULT 'ai'
```

`id` 保持应用层生成的 `wo-xxx`；新增服务端生成的 `order_no` 不适用——
工单号沿用 `WO` 前缀 + 8 位十六进制，作为对外可见编号。

已有种子数据补齐默认值。

## 工具设计

### `create_work_order`

| 参数 | 类型 | 校验 |
|---|---|---|
| `order_no` | str | 必填，`^[A-Z0-9]{8,32}$` |
| `issue_type` | enum | 必填，见下 |
| `description` | str | 必填，10–500 字 |

**问题类型枚举**
`运输破损` / `发货延迟` / `质量问题` / `退换货` / `其他`

**服务端强制项**（不由模型传入）
- `visitor_id` ← ToolRuntime 注入
- `product_id` ← 由 `order_no` 反查该顾客的历史工单或商品表；查不到则留空
- `status` ← 固定 `待处理`
- `source` ← 固定 `ai`

**返回**
- 成功：`{"created": true, "work_order_no": "WO...", "status": "待处理"}`
- 重复：`{"created": false, "reason": "duplicate", "existing_work_order_no": "..."}`
  并附提示「该订单已有同类未完结工单，请告知顾客正在处理中，不要重复提交」

### 参数校验

沿用现有模式：Pydantic 校验失败返回结构化错误，模型自行纠正。
`description` 过短（<10 字）时提示补充细节，避免「坏了」这类无法处理的工单。

## 幂等与防重复

唯一性判定：`(visitor_id, order_no, issue_type)` 且 `status != '已完结'`。

不做数据库唯一索引——状态会变化，唯一索引会阻止合法的新建。
改为**写入前先查**：命中未完结同类工单则返回 duplicate，不写入。

并发下可能产生两条重复工单，本地单机场景可接受，不做锁。

## Prompt 变更

在工具规则中补充：

- 顾客描述问题且需要跟进时，先查订单，再复述工单内容请顾客确认
- **顾客未明确同意前，不得调用 create_work_order**
- 顾客拒绝或改口时，不建单，按顾客新要求处理
- 建单成功后告知工单号与当前状态，不承诺处理时限

## 验收标准

1. 顾客说「杯子裂了」→ AI 询问订单号 → 确认信息 → 请顾客确认 → 建单成功并返回工单号
2. 顾客在建单提议环节说「先不用」，AI 不建单
3. 同一订单同类型再次建单 → 返回重复提示，不新增记录
4. 同一订单不同类型可正常建单
5. 顾客 A 无法为顾客 B 的订单建单（订单归属校验）
6. 描述少于 10 字时模型被要求补充
7. 数据库中新工单 `visitor_id` 正确、`source='ai'`、`status='待处理'`
8. `uv run pytest` 全绿

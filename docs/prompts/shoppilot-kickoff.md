## 交互约定

- 需求不明确时用 AskUserQuestion 弹窗给选项，不要用纯文字提问
- 一旦拍板的方案直接实施，不要反复确认
- 全程中文交流
- 我可能随时说「跳过提问，开干」，此时直接执行并说明你替我做的主决定

## 技术栈（已定，不再讨论）

| 层 | 选型 |
|---|---|
| 模型接入 | OpenAI 兼容接口，`ChatOpenAI(base_url=...)`，换供应商只改 `.env` |
| 编排 | LangChain |
| 后端 | FastAPI，对话走 SSE 流式 |
| 存储 | SQLite 标准库 |
| 前端 | 单页 HTML + 原生 JS，不引框架 |
| 环境 | uv + Python 3.13 |

## 工作方式

1. 先给方案（结构、接口、数据模型、非目标），我说开工再动手
2. 设计文档写到 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
3. 实施计划写到 `plans/` 下，带可勾选清单
4. 每个可验证的步骤一个提交，分支用 `main`
5. 完成后**在浏览器实跑验收**，不能只跑单测就说完成

## 留痕规则

- 提交信息说明「为什么」，不是「做了什么」
- 计划文档逐项打勾，进度可回溯
- `.env` 永不入库，key 只走本地配置

## 已知边界

- 顾客身份靠浏览器 `localStorage` 的 `visitor_id`，换设备即新顾客
- 人设 prompt 禁止编造具体政策、价格、时效
- 阶段一不含：登录、多用户隔离、知识库、订单工具、转人工、部署

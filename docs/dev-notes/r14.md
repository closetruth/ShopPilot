# r14 开发留痕

## 2026-10-30 · 起因

### 关键原话

> 检索不到或证据置信度低 会硬编答案吗现在

> 多测

> * 回答带引用编号,编号能映射回来源 chunk 的章节路径、跳回原文
> * 检索不到或证据置信度低就显式拒答,不硬编答案
> * 生成阶段让模型自评召回的知识够不够答这个问题,不够则拒答,并把问题
>   落进低置信度问题池

> 悬停显示条例
> 只用分数判定
> 先做这三条

### 关键产出

- 设计：`docs/superpowers/specs/2026-10-30_r14-citation-refusal-design.md`
- 计划：`docs/plans/2026-10-30_r14-citation-refusal-plan.md`
- 提示词：`docs/prompts/2026-10-30_r14-citation-refusal-prompt.md`

### 实测发现

**18 条边界测试**（3 条明显域外 + 15 条政策边缘），16 条表现良好：

- PLUS 会员退运费 → 准确说出「是运费险折扣，并非全额免」
- 超过 15 天能退吗 → 正确区分七天无理由与质量问题两档
- 双 11 补差价 → 15 天内、促销差异不算、500 元内自动，数字全对

**1 条硬编**：

> 问：「买一送一的商品能退一件吗」
> 答：「知识库里没有查到…**一般来说，赠品或赠送件需与主商品一并退回，
> 才能按实付金额退款。**」

前半句正确拒答，后半句是编的。47 条政策里没有一条提到赠品退货。
「一般来说」是把编造包装成常识——比直接编更难发现。

**2 条正确拒答**：同城配送当天到、买一送一（前半句）。

### 我的判断

现有防线只有 prompt 一句「不要编造」。这能挡住明显域外问题（花呗、
报关），但挡不住「检索到了、证据不足」的边界情况——模型觉得自己有依据。

三条改造里，第二条（结构性拒答）最关键：证据不足时**清空 results**，
只给 insufficient 标记。模型没有素材就不会编。

### 待复核

阈值从 0.58 上调到 0.65 是我的判断，没有数据支撑。r13 的评估跑完后
应该用实际分数分布校准。

## 2026-10-30 · 阈值挡不住的场景（遗留问题）

### 现象

结构化拒答上线后实测三条：

| 问题 | max_score | 判定 | 是否正确 |
|---|---|---|---|
| 退货运费谁出 | 0.73 | 充分 | ✅ |
| 明天几点开会 | 0.52 | 证据不足 | ✅ |
| **买一送一的商品能退一件吗** | **0.6574** | **充分** | ❌ 漏了 |

「买一送一」0.6574，刚好越过 0.65 门槛。检索到三条：

```
P-REF-001-3  0.6574  已签收场景（仅退款规则）
P-MEM-001-2  0.6491  极速退款规则
P-REF-003-1  0.633   自动审批额度
```

**没有一条在讲赠品或买一送一**。三条都是「退款」大类下的通用规则，
语义沾边（都在讲退款金额），但答不了「赠品能不能单独退」。

### 根因

纯分数阈值无法区分：

- 「这条规则**回答了**问题」
- 「这条规则**也在退款这个大类里**」

模型拿到这三条，很可能又编出「一般来说，赠品需与主商品一并退回」——
和 r14 要解决的问题一模一样，只是这次是被阈值判断放行导致的。

### 候选方案（未实施）

**词面覆盖校验**：在返回前检查 query 的核心实词是否出现在命中内容里。

```python
query_terms = set(tokenize(query)) - stopwords
covered = union(tokenize(r.title + r.section + r.content) for r in results)
missing = query_terms - covered
if len(missing) / len(query_terms) > 0.5:
    → insufficient
```

「买一送一」「赠品」在三条结果里都没出现 → 判为证据不足。

**代价**：同义表达会误判。顾客说「退货」政策写「退回」，字面对不上，
但语义完全一致——这会把好答案也拒掉。

**折中**：只对 query 里「非通用业务词」做校验。先建一份通用词表
（退货、退款、运费、订单…），校验时排除它们，只看「赠品」「买一送一」
这类具体实体。

### 决定

用户指示**先记录，后面再处理**。本轮不做词面校验，阈值维持 0.65。

### 影响

r14 的结构性拒答能挡住：
- 明显域外问题（花呗、报关）
- 完全无关问题（明天几点开会）

**挡不住**：
- 语义沾边但实体不匹配的问题（买一送一）
- 这类问题仍可能触发模型补编

上线前需要解决方案，否则「不硬编」这个承诺只兑现了一半。

### 我拒绝或纠偏了什么

builder check 提了四个问题，用户裁定三件：

- **「包装破了」不为单条硬调词条**——改写后 0.643 差 0.007 过闸，
  继续调术语组合性价比不高。验收放宽为「显著提升，可能仍拒答」。
  （后续反转：术语改成与 FAQ 原文对齐的「破损 质量问题退换货」后
  实测 0.683 过闸——放宽的裁定反而被术语存在性测试要求的对齐救了）
- **「要投诉你们的服务」冻结测试更新为新行为**——r14 曾固化它必须
  拒答；改写后 0.812 命中投诉处理条款。口语投诉拿到投诉处理原则 +
  转人工指引，优于生硬拒答
- **轨迹走 state 加字段**——rewritten_terms/rewritten_query/
  fallback_used 从检索节点经 state 到 main 落 trace detail

### 翻车与返工

- **验收暴露意图层盲区（本轮最大发现）**：「包装破了」被 LLM 兜底
  判成投诉（0.75——模型把「破了」理解成情绪），「快递好久没动」
  判成查件（business）。改写前这些 query 根本到不了检索（被闸挡），
  所以问题从未暴露；r16 让它们能到检索了，意图层的误判浮出水面。
  修法：售后诉求描述词（坏了/破了/没动静/丢件族）在意图规则层直接
  钉 knowledge，零 LLM 调用（0c8622b）
- **词表术语必须对齐 FAQ 原文**：「运输破损」在知识库里不存在
  （原文只说「破损」「质量问题」），术语存在性测试逼着词表改写——
  这个约束反而带来了「包装破了」的意外过闸
- **正则触发词漏变体**：「快递好久没动」含「没动」但词表只写了
  「不动了」；测试样本驱动补齐
